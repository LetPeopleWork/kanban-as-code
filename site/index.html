Your work items and their history, as plain files in git

Keep your work items and their full history as plain files in git, in an open format that any tool can read. It is designed so that your flow data outlives any one tool, and so that it works on any git host.

We define the middle only. Everything on the left and the right is a tool, and any tool can be yours. Git holds the files and records who changed them. No reader has to speak git, and no host API is used.

Why a standard and not a tool

Tools that kept issues in git have existed for years: ditz, TicGit, Bugs Everywhere. Each had its own format, and when the tool went quiet, so did the format. A format that belongs to one tool lives as long as that tool.

Other formats exist today: Backlog.md, git-bug, todo.txt and several newer markdown task formats for agents. We know them and learned from them. What this draft adds is the history inside each card, and a workflow file with the states, the WIP policy and the service level expectation, as the Kanban Guide asks for.

This standard defines the files only. It defines no board, no chart and no forecast. Those are the job of the tools that read the files.

What you can build on

Core, stable

  • File layout: a workflow file and a cards/ folder
  • Workflow: key, states with the categories todo, doing and done; how WIP is controlled and the policies in the body; optional SLE
  • Card: id, title, status, transitions; tools keep fields they do not know
  • History: append only, the last entry equals status, start and finish dates derived from it
  • A move is one change to one file

Draft, may change

  • Cards in other folders, branches or repos
  • References across repos
  • parent and dependencies
  • Other optional fields, such as labels or blocked
  • The open questions at the end of the spec

We will not change the core without announcing it first: a new version number, a dated changelog line, and a direct message to everyone who has told us they build on it. This is a promise about how we behave, not a guarantee that the core is right. We are building a writer and a reader ourselves, and they may prove a core rule wrong.

Questions

Why not GitHub Issues with a coding agent?

Here the cards are files in your repo, with their whole history in each file. The standard is designed to work on any git host: GitHub, GitLab, Gitea, Forgejo or your own server. So far we have checked it on GitHub.

Why not Backlog.md?

Backlog.md is prior art, and we learned from it. This draft keeps the history inside each card and adds a workflow file with the WIP policy and the SLE. We make no compatibility claim.

Who owns this?

For now, LetPeopleWork wrote it. There is no standards body and no neutral owner yet. The standard is under CC BY 4.0, so anyone can use it.

Is it stable?

The core is stable enough to build on, and we announce any change to it. The rest is a draft.
